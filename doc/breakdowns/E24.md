# E24 — White-label + flag `is_actvet`

> **Breakdown gerado em 2026-04-26.** Spec consolidada em `doc/15-roadmap-pos-mvp.md` (F15, linhas 867–935).

## Contexto

Habilitar customização visual por professor (logo + nome) na navbar e diferenciar branding "Actvet/Skills Hub" dos demais professores. A flag `is_actvet` é **por professor** (mora em `tenants` porque cada prof = 1 tenant). Pré-requisito de E25 (LO) e E26 (Reports).

**Backfill prod:** super-admin marca os professores Actvet existentes via toggle no `/admin/teachers/edit` (painel administrativo) — sem SQL manual.

---

## Story E24-01: Flag `is_actvet` + schema + cadastro/edição super-admin

**Como** super-admin, **quero** marcar um professor como "Actvet" no cadastro e na edição **para que** o tenant dele use o branding Skills Hub e fique elegível para LO/Reports nos épicos seguintes.

**Complexidade:** P
**Depende de:** nenhuma
**Persona:** super-admin

### Critérios de Aceite
- [ ] `install/schema.sql` ganha as 3 colunas em `tenants`: `is_actvet TINYINT(1) NOT NULL DEFAULT 0`, `platform_name VARCHAR(60) NULL`, `logo_path VARCHAR(255) NULL` — idempotente
- [ ] Form `/admin/teachers/new` exibe toggle "É Actvet?" (checkbox), padrão off
- [ ] Form `/admin/teachers/edit` exibe toggle "É Actvet?" — permite alternar em professores existentes (backfill)
- [ ] Submit cria/atualiza `tenants.is_actvet` corretamente
- [ ] Listagem `/admin/teachers` exibe badge "Actvet" para professores com flag setada
- [ ] Acesso bloqueado para quem não é super-admin (`require_role('super_admin')`)
- [ ] CSRF no form

### Tarefas técnicas
- [ ] Rodar `/mysql-schema` para o ALTER TABLE (3 colunas)
- [ ] Atualizar Model `Tenant` (insert/update aceita `is_actvet`)
- [ ] Atualizar `src/pages/admin/teachers/new.php` e `edit.php` (form + handler)
- [ ] Atualizar `src/pages/admin/teachers/index.php` (badge na listagem)
- [ ] Auditar SELECTs explícitos em `Tenant::find/list` — adicionar as 3 colunas novas onde necessário
- [ ] `lang/pt.php` + `lang/en.php`: chaves `admin.teachers.is_actvet_label`, `admin.teachers.is_actvet_hint`, `admin.teachers.badge_actvet`
- [ ] Mobile: validar form em 360px
- [ ] `php -l` antes do commit

## Story E24-02: Helper `tenant_branding()` + render na navbar

**Como** professor/aluno, **quero** ver o nome e logo do meu tenant na navbar **para que** a plataforma reflita a identidade do meu professor (Skills Hub no Actvet, customizado nos demais).

**Complexidade:** P
**Depende de:** E24-01
**Persona:** professor + aluno (qualquer user logado)

### Critérios de Aceite
- [ ] Helper `tenant_branding(int $tenantId): array{name: string, logo_url: string}` em `src/helpers.php`
- [ ] Resolução do `name`:
  - se `tenants.platform_name` não NULL → usa o valor
  - senão se `is_actvet=1` → `'Skills Hub'`
  - senão → `'LMS'`
- [ ] Resolução do `logo_url`:
  - se `is_actvet=1` → `/assets/logos/actvet.png` (built-in, ignora `logo_path`)
  - senão se `tenants.logo_path` não NULL → URL do upload
  - senão → fallback genérico `[L]` (placeholder atual)
- [ ] `src/templates/header.php` consome o helper e renderiza nome + logo (substitui `[L] LMS` hardcoded)
- [ ] Asset `public/assets/logos/actvet.png` já versionado no repo (✅ confirmado)
- [ ] Aluno em professor Actvet vê "Skills Hub" + logo Actvet
- [ ] Professor não-Actvet sem customização vê fallback `[L] LMS`
- [ ] Mobile: navbar 360px renderiza logo+nome sem quebra

### Tarefas técnicas
- [ ] Implementar `tenant_branding()` em `helpers.php` (cache em memória por request via `static $cache = []`)
- [ ] Atualizar `header.php`
- [ ] CSS leve no header se necessário (limite de altura da imagem)
- [ ] `lang/pt.php` + `lang/en.php`: chave `branding.default_name`
- [ ] Mobile QA em 360px

## Story E24-03: Customização visual em `/teacher/settings` (nome + upload de logo)

**Como** professor, **quero** customizar o nome da plataforma e fazer upload de uma logo **para que** meu tenant tenha identidade visual própria; se for Actvet, só posso editar o nome (logo travada).

**Complexidade:** M
**Depende de:** E24-01 (precisa das colunas) + E24-02 (helper já consumido)
**Persona:** professor

### Critérios de Aceite
- [ ] `/teacher/settings` ganha seção "Identidade visual" com 2 campos:
  - **Nome da plataforma**: input text, max 60 chars, opcional (NULL = fallback)
  - **Logo**: input file, só visível se `!is_actvet`
- [ ] Quando `is_actvet=1`: campo Logo escondido + hint "Logo Actvet padrão (não editável)" com thumbnail da logo built-in
- [ ] Upload de logo:
  - extensões aceitas: `png`, `svg`, `jpg`, `jpeg`
  - tamanho máx **500KB**
  - validação de mime real via `finfo_file`
  - destino: `public/uploads/logos/<tenant_id>-<timestamp>.<ext>`
  - apaga arquivo antigo se houver (substituição)
- [ ] Submit filtra por `tenant_id` do professor logado (helper `current_tenant_id()` via `tenants.owner_user_id`)
- [ ] Professor Actvet que tenta forçar upload via DevTools/POST manual: rejeitado server-side (validação `if ($tenant['is_actvet']) { ignore logo }`)
- [ ] Validação: nome com mais de 60 chars rejeitado com mensagem clara
- [ ] Após salvar, navbar reflete imediatamente
- [ ] CSRF no form
- [ ] Sanitização do nome no render via `e()`
- [ ] Mobile: form usável em 360px

### Tarefas técnicas
- [ ] Atualizar página `/teacher/settings` (form + handler)
- [ ] Service de upload de logo (validação mime, finfo)
- [ ] Model `Tenant::updateBranding(int $tenantId, ?string $name, ?string $logoPath)` — respeitando regra Actvet
- [ ] Garantir diretório `public/uploads/logos/` (`.gitkeep` ou criação on-demand)
- [ ] `lang/pt.php` + `lang/en.php`: chaves `teacher.settings.branding_section`, `teacher.settings.platform_name_label`, `teacher.settings.logo_label`, `teacher.settings.logo_hint_actvet`, `teacher.settings.logo_invalid_mime`, `teacher.settings.logo_too_large`, `teacher.settings.platform_name_too_long`
- [ ] Auditar SELECT explícito em queries de `/teacher/settings` (incluir `is_actvet`, `platform_name`, `logo_path`)
- [ ] Mobile QA 360px
- [ ] `php -l`

## Story E24-04: Defaults de provisioning Actvet (avatar_style + platform_name)

**Como** super-admin, **quero** que ao cadastrar um professor com toggle Actvet os defaults `avatar_style='arabe'` e `platform_name='Skills Hub'` sejam aplicados (e não-Actvet padrão `avatar_style='ocidental'`) **para que** o tenant já nasça com a identidade correta sem edição manual.

**Complexidade:** P
**Depende de:** E24-01
**Persona:** super-admin

### Critérios de Aceite
- [ ] No INSERT de `tenants` em `/admin/teachers/new`:
  - `is_actvet=1` → `avatar_style='arabe'`, `platform_name='Skills Hub'`
  - `is_actvet=0` → `avatar_style='ocidental'`, `platform_name=NULL`
- [ ] Professor pode alterar `avatar_style` depois em `/teacher/settings` (já implementado em E17-04 — não regredir)
- [ ] Professor pode alterar `platform_name` depois (E24-03)
- [ ] Tenants existentes em prod **não são afetados** — defaults só valem em INSERT novo
- [ ] Smoke: cadastrar 2 tenants de teste (1 Actvet, 1 não), conferir defaults no DB

### Tarefas técnicas
- [ ] Atualizar handler de `/admin/teachers/new` com lógica condicional
- [ ] `php -l`
