# E27 — Dark mode (preferência aluno)

> **Breakdown gerado em 2026-04-26.** Spec consolidada em `doc/15-roadmap-pos-mvp.md` (F18, linhas 1109–1131).

## Contexto

Preferência visual do **aluno** (não setting de tenant). Hoje `lms-student-area` usa fundo claro fixo (`#F8F7FB` + tons claros nos cards); falta alternativa pra ambientes com pouca luz ou preferência pessoal.

**Decisões simplificadoras:**
- Apenas pra aluno no MVP (professor/super-admin ficam light)
- Sem auto-detecção via `prefers-color-scheme` (toggle explícito)
- Sem por-tenant override (preferência sempre do aluno)
- Aplicação via class no `<body>` (`lms-theme-dark`) — escopo único pra overrides de tokens

---

## Story E27-01: Schema + persistência

**Como** aluno, **quero** que minha preferência de tema persista entre sessões e dispositivos **para que** eu não precise re-configurar a cada login.

**Complexidade:** P
**Depende de:** nenhuma
**Persona:** aluno

### Critérios de Aceite
- [ ] `install/schema.sql`: ALTER `users` ADD COLUMN `theme ENUM('light','dark') NOT NULL DEFAULT 'light'` AFTER `language` (idempotente via PREPARE/EXECUTE)
- [ ] CREATE TABLE `users` atualizado pra fresh installs
- [ ] `AuthController::authenticate` SELECT inclui `theme`; `$_SESSION['user']['theme']` populado
- [ ] Auditar outros loaders de user que populam session (se houver)
- [ ] Helper `current_user_theme(): string` em `src/helpers.php`: `'light'` ou `'dark'` (default `'light'` quando não-aluno ou não setado)
- [ ] Handler POST `/profile/theme`: valida whitelist, atualiza DB + session, redirect 303
- [ ] Restrição: handler 403 quando não-aluno
- [ ] CSRF

### Tarefas técnicas
- [ ] Rodar `/mysql-schema`
- [ ] Atualizar `install/schema.sql`
- [ ] Auditar `AuthController::authenticate`
- [ ] Implementar `current_user_theme()`
- [ ] Criar handler `/profile/theme` + registrar rota
- [ ] `php -l`

## Story E27-02: Toggle UI em /profile

## Story E27-03: CSS dark variants

**Como** aluno em modo dark, **quero** que toda a interface respeite o tema escuro sem perder legibilidade **para que** a experiência fique confortável em qualquer ambiente.

**Complexidade:** M
**Depende de:** #E27-01 (helper); pode ir paralelo a #E27-02
**Persona:** aluno

### Critérios de Aceite
- [ ] `<body>` ganha class `lms-theme-dark` quando `current_user_theme() === 'dark'` (em `layout.php`)
- [ ] `student-area.css` ganha block `body.lms-theme-dark { ... }` que sobrescreve tokens existentes:
  - `--lms-bg`, `--lms-card-bg`, `--lms-text`, `--lms-text-muted`, `--lms-neutral-100..900`, `--lms-shadow-card`, `--lms-border`, etc.
- [ ] Componentes revisados visualmente em dark:
  - **Sidebar** (avatar, nome, XP bar, achievement icons, ranking pill)
  - **Course card** (cover, progress bar, badges)
  - **Achievement grid** (cards locked/unlocked)
  - **Ranking grid** (tabela + cards mobile)
  - **Course/CU/Activity/Evaluation pages** (header, content card, alert variants)
  - **Profile** (form, badges, novo bloco "Aparência")
  - **Header navbar** — decidir: deixa branca em dark ou inverte
- [ ] Contraste mínimo WCAG AA pra texto (4.5:1)
- [ ] Sem flash of light theme (FOUT) — class no body é setada antes do CSS carregar

### Tarefas técnicas
- [ ] `layout.php`: aplica class no `<body>`
- [ ] `student-area.css`: dark token block + component overrides
- [ ] Validar contraste WCAG (Lighthouse ou ferramenta manual)
- [ ] Mobile QA dark
- [ ] `php -l`

## Pendências esperadas

- **Touch áreas teacher/admin** ficam light no MVP. Se PO pedir dark mode universal depois, casa com E29 (identidade visual unificada teacher+admin) ou vira E27.5 separada.
- **Contraste WCAG**: revisão visual + medição de 1-2 pares de cor crítico (texto sobre card, badge sobre fundo). Ajustes finos podem virar pendência.
- **Cobre só pages student-area**: pages como `/profile` (que ganhou sidebar do aluno em E24-fix), `/notifications` etc. precisam ter dark aplicado também — o tokens hoje já estão em `student-area.css` que carrega em todas elas.
