# E25 — Learning Outcomes (Actvet-only)

> **Breakdown gerado em 2026-04-26.** Spec consolidada em `doc/15-roadmap-pos-mvp.md` (F16, linhas 939–1017).

## Contexto

Modo de avaliação alternativo a "nota": professor define **exatamente 5 learning outcomes por UC**; ao avaliar, dá nota 0-10 pra cada LO; nota final = média (gravada em `evaluation_submissions.grade` pra compat com queries existentes).

**Disponibilidade restrita a Actvet** (decisão simplificadora): não-Actvet tem `grading_mode='grade'` forçado server-side; UI esconde o conceito inteiramente. Reduz superfície de teste e simplifica regras.

**Pré-requisito:** E24 (`is_actvet` flag) — já fechado em v0.21.0.

---

## Story E25-01: Schema + LearningOutcome model + grading_mode em courses

**Como** professor Actvet, **quero** que o sistema suporte os modelos de dados de Learning Outcomes e o select `grading_mode` no form de curso **para que** as próximas stories possam construir UI e regras em cima.

**Complexidade:** P
**Depende de:** nenhuma (E24 já fechado em prod)
**Persona:** professor (Actvet)

### Critérios de Aceite
- [ ] `install/schema.sql`:
  - ALTER `courses` adiciona `grading_mode ENUM('grade','learning_outcomes') NOT NULL DEFAULT 'grade'` AFTER `eval_after_activities` (idempotente via PREPARE/EXECUTE)
  - `CREATE TABLE IF NOT EXISTS learning_outcomes` (id, cu_id FK CASCADE, description VARCHAR(500), position INT, idx por (cu_id, position))
  - `CREATE TABLE IF NOT EXISTS evaluation_submission_lo_grades` (PK composite submission_id+lo_id, FKs CASCADE em ambas direções, CHECK grade BETWEEN 0 AND 10)
- [ ] Model `LearningOutcome` em `src/models/LearningOutcome.php` com pelo menos: `findByCu(int $cuId): array`, `replaceForCu(int $cuId, array $descriptions): void` (substitui atomicamente — DELETE + INSERT N novos em transação)
- [ ] `Course` model auditado: queries com SELECT explícito que retornam linhas de `courses` incluem `grading_mode`
- [ ] Form `/teacher/courses/{id}/edit` ganha select "Modo de avaliação" — visível apenas se `tenant.is_actvet=1`; opções: "Nota (0-10)" / "Learning Outcomes (5 critérios)"; default `'learning_outcomes'` em curso novo Actvet, `'grade'` em não-Actvet (também escondido)
- [ ] Defesa server-side no handler: se POST tenta setar `grading_mode='learning_outcomes'` em tenant não-Actvet, força `'grade'` silenciosamente

### Tarefas técnicas
- [ ] Rodar `/mysql-schema` para os 3 itens de schema
- [ ] Criar `src/models/LearningOutcome.php`
- [ ] Auditar `Course` (`src/models/Course.php`) e adicionar `grading_mode` aos SELECTs explícitos relevantes
- [ ] Atualizar `/teacher/courses/{id}/edit` (form + handler) com select condicional
- [ ] `lang/pt.php` + `lang/en.php`: chaves `courses.grading_mode.label`, `courses.grading_mode.option.grade`, `courses.grading_mode.option.learning_outcomes`
- [ ] Atualizar `install/schema.sql`
- [ ] Mobile: validar 360px
- [ ] `php -l` antes do commit

## Story E25-02: Form do professor pra cadastrar 5 LOs por UC

**Como** professor Actvet com curso em LO mode, **quero** cadastrar exatamente 5 learning outcomes por unidade de competência **para que** as avaliações dessa UC possam ser corrigidas por critério.

**Complexidade:** M
**Depende de:** #E25-01 (schema + model)
**Persona:** professor (Actvet)

### Critérios de Aceite
- [ ] Nova página `/teacher/cu/{id}/learning-outcomes` (ou seção inline na edição da CU — decisão durante a story; preferir tela separada se polui muito a edição)
- [ ] 5 inputs de descrição (textarea ou input curto, max 500 chars cada), numerados 1-5
- [ ] Validação:
  - Todos os 5 obrigatórios e não-vazios ao salvar
  - Cada um com max 500 chars (matches schema VARCHAR(500))
  - Se algum vazio: erro por campo + form preserva conteúdo digitado
- [ ] Save em transação: `LearningOutcome::replaceForCu($cuId, [d1, d2, d3, d4, d5])` apaga os existentes + insere os 5 novos com `position = 1..5`
- [ ] Acesso restrito: rejeita 403 quando (a) tenant não-Actvet, (b) curso não está em LO mode, (c) CU não pertence ao tenant logado
- [ ] CSRF no form
- [ ] Sanitização do display via `e()` (descrição é texto livre)
- [ ] Preview/leitura: mostra os 5 LOs cadastrados com badge "5/5 cadastrados" (ou "X/5 — incompleto" se nunca foi salvo, mas como o save exige 5, esse estado só ocorre antes de qualquer save)
- [ ] Link "Editar critérios" na página de edição da CU (visível apenas em LO mode + Actvet)

### Tarefas técnicas
- [ ] Criar página `/teacher/cu/{id}/learning-outcomes` (form + handler) — registrar rota em `src/routes.php`
- [ ] Implementar `LearningOutcome::replaceForCu` em transação atômica
- [ ] Adicionar link condicional na edição da CU
- [ ] `lang/pt.php` + `lang/en.php`: ~8 chaves (`learning_outcomes.title`, `learning_outcomes.help`, `learning_outcomes.field_n`, `learning_outcomes.placeholder`, `learning_outcomes.err.required`, `learning_outcomes.err.too_long`, `learning_outcomes.success`, `learning_outcomes.edit_link`)
- [ ] Mobile: validar 360px (5 textareas empilhados)
- [ ] `php -l`

## Story E25-03: Form de feedback adapta — 5 inputs de LO + média auto

**Como** professor Actvet corrigindo avaliação em curso LO mode, **quero** dar nota 0-10 pra cada um dos 5 learning outcomes da UC **para que** a média seja calculada automaticamente e a avaliação fique granular.

**Complexidade:** M
**Depende de:** #E25-01 (schema) + #E25-02 (LOs cadastrados)
**Persona:** professor (Actvet)

### Critérios de Aceite
- [ ] Tela `/teacher/evaluation/{id}/submission/{sid}` detecta `course.grading_mode='learning_outcomes'` e renderiza UI alternativa:
  - Lista os 5 LOs da UC (descrição + input number 0-10 com step 0.1 cada)
  - JS calcula média em tempo real e exibe ("Nota final: 7.5")
  - Submit valida: cada nota entre 0 e 10
- [ ] Server-side: handler grava em `evaluation_submission_lo_grades` (5 rows) e calcula média → grava em `evaluation_submissions.grade` (DECIMAL(3,1)) — mantém compat com queries que leem `.grade`
- [ ] Transação atômica: `INSERT/REPLACE` nos 5 LO grades + UPDATE no submission grade num único `Database::tx`
- [ ] Reusa as regras existentes: aprovação >=6 desativa retry; XP >=8; etc. (a média é a "grade" pros propósitos de regra)
- [ ] Quando curso é `grade` mode (não-LO), UI continua igual (1 input de nota)
- [ ] Quando UC não tem 5 LOs cadastrados (caso de borda — curso virou LO depois de criar UC), exibe alerta "Cadastre 5 critérios antes de corrigir" com link pra E25-02
- [ ] Acesso restrito: rejeita 403 quando tenant não-Actvet (defesa redundante; o curso não estaria LO se não-Actvet)
- [ ] CSRF + sanitização
- [ ] Mobile: 5 inputs empilhados em 360px

### Tarefas técnicas
- [ ] Detectar grading_mode na page handler
- [ ] Service `EvaluationFeedbackService::gradeByLO(submissionId, [loId => grade])` em transação
- [ ] Renderizar UI alternativa (parcial via if/else no template existente, ou partial separado)
- [ ] JS leve pra calcular média em tempo real (Alpine.js ou vanilla)
- [ ] `lang/pt.php` + `lang/en.php`: ~5 chaves (`evaluations.feedback.lo_mode_title`, `lo_grade_label`, `lo_average`, `lo_err.range`, `lo_err.uc_not_ready`)
- [ ] Mobile QA
- [ ] `php -l`

## Ordem de implementação

1. **E25-01** — schema + model + grading_mode no curso; destrava todo o resto
2. **E25-02** — cadastro de 5 LOs por UC (sem isso, E25-03 não tem o que renderizar)
3. **E25-03** — feedback do professor por LO (sem isso, E25-05 não tem grades pra mostrar)
4. **E25-04** — esconder quiz (independente; pode ser feito em paralelo a 02/03 mas pequeno)
5. **E25-05** — aluno vê critérios + notas (depende de 03)
6. **E25-06** — polish + smoke + i18n batch + doc

Cada story = 1 PR pra `develop`. Release MINOR (`v0.22.0`) ao fim do épico.

## Pendências esperadas

- Caso de borda: curso virou LO depois de UCs já existirem sem 5 LOs cadastrados → tratar com alerta no feedback (E25-03) e talvez criar wizard de cadastro guiado (decisão durante o épico).
- Notas decimais: spec diz DECIMAL(3,1) por LO; média final também DECIMAL(3,1). Verificar truncamento/arredondamento se a soma /5 produzir mais de 1 decimal.
