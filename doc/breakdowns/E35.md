# E35 — Widgets interativos (F26)

> **Breakdown gerado em 2026-06-08.** Spec em `doc/24-widgets.md` + `doc/15-roadmap-pos-mvp.md` (F26). Decisão em **ADR-037**.

## Contexto

O PO quer criar **widgets** — mini-apps interativas num `.zip` (HTML+CSS+JS+imagens, ex.: calculadora) — e inseri-las no conteúdo de uma CU, aparecendo pro aluno junto ao material. No cadastro escolhe **inline** (embutido) ou **window** (ícone → nova janela). JS arbitrário do professor exige **isolamento forte**.

## Decisões consolidadas (2026-06-08) — ADR-037 / `doc/24-widgets.md`

- Pacote zip com `index.html` na raiz.
- Isolamento por **`<iframe sandbox="allow-scripts">` sem `allow-same-origin`** (origem nula) + **CSP restritiva**.
- Storage **fora do document root**, servido por endpoint PHP de passthrough.
- Upload seguro: limite MB, finfo de zip, **zip-slip guard**, allowlist de extensões internas (rejeita `.php`), exige `index.html`.
- Biblioteca **compartilhada no curso**: widget pertence ao tenant que cadastrou; picker em curso compartilhado oferece widgets de todos os colaboradores. Editar/remover = dono; inserir = qualquer professor com acesso.
- Placeholder `[[widget:ID]]` no conteúdo (sobrevive ao HTML Purifier); expandido no render.

## Restrições

- **Segurança é o eixo do épico.** Nenhum arquivo do widget pode ser executado no servidor (storage fora do webroot + allowlist). O JS do widget nunca acessa a sessão do LMS (sandbox de origem nula).
- Compatível com migração futura a GCS (ver [[project_future_gcs_storage]]) — não acoplar a `public/uploads/`.
- Multi-tenant, i18n PT/EN, mobile 360px.

## Story E35-02: Upload + extração segura do zip

**Como** professor, **quero** subir o `.zip` do widget **para que** ele fique disponível pra inserir no conteúdo.

**Complexidade:** M-G · **Depende de:** E35-01 · **Persona:** professor / backend (segurança)

### Critérios de Aceite
- [ ] Upload com `csrf_verify()` + `require_role('teacher')`; limite de MB definido (sugerido 10–12 MB)
- [ ] `finfo_file` confirma zip real
- [ ] **Zip-slip guard:** rejeita entradas com `..`, caminho absoluto ou que escapem da pasta destino
- [ ] **Allowlist de extensões internas** (html/htm/css/js/json/png/jpg/jpeg/gif/webp/svg/woff/woff2/ttf/map); **rejeita** `php`/`phtml`/`phar`/executáveis
- [ ] Exige `index.html` (ou `entry_file`) na raiz; senão erro claro
- [ ] Extração para **`storage/` fora do document root** (`storage/widgets/tenant_<id>/<slug>/...`)
- [ ] Re-upload substitui os arquivos (mesma `id`/`slug`); limpa a pasta antiga
- [ ] Erros tratados sem vazar `Throwable::getMessage()` ao usuário (logar + mensagem genérica)

### Tarefas técnicas
- [ ] Service de upload/extração (ZipArchive) com guards
- [ ] Helper de storage (criar/limpar pasta; preparado pra trocar backend → GCS)
- [ ] `php -l`

### Riscos
- **Zip-slip / path traversal:** testar com zip malicioso (entrada `../../x`). Bloquear.
- **Arquivo executável no zip:** confirmar que `.php` é rejeitado e que mesmo se passasse não roda (storage fora do webroot + serving por passthrough).

## Story E35-04: Endpoint de serving sandboxed + página window

**Como** sistema, **quero** servir os arquivos do widget de forma isolada **para que** o JS do professor rode sem comprometer o LMS.

**Complexidade:** M-G · **Depende de:** E35-02 · **Persona:** backend (segurança)

### Critérios de Aceite
- [ ] `GET /widget/serve/{id}/<path>` faz stream dos bytes de `storage/widgets/.../<path>`
- [ ] **Content-type por allowlist de extensão**; `X-Content-Type-Options: nosniff`
- [ ] **CSP restritiva** na resposta (`default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src 'self' data:`)
- [ ] **Anti path-traversal:** caminho resolvido confinado à pasta do widget; rejeita `..`/absoluto
- [ ] **Gate de acesso:** sessão autenticada + (professor com acesso ao curso onde o widget aparece **ou** aluno matriculado em curso cujo conteúdo referencia o widget)
- [ ] `GET /widget/open/{id}` — página full-page do modo `window` (carrega o widget no mesmo iframe sandbox, em tela cheia)
- [ ] Nenhum arquivo do widget executa no servidor (servido como bytes, nunca via include)

### Tarefas técnicas
- [ ] Endpoint de passthrough + mapa de content-type
- [ ] Resolver acesso (reusar helpers de curso/matrícula)
- [ ] Página `/widget/open/{id}`
- [ ] `php -l`

### Riscos
- **Cookies no fetch do iframe:** ok — a requisição same-origin carrega o cookie (auth funciona); o sandbox bloqueia só o JS de ler `document.cookie`. Documentar no PR.
- **Apache servindo `.php`:** mitigado por storage fora do webroot + serving por passthrough; confirmar em prod (Hostinger).

## Story E35-05: Integração no editor (TinyMCE) + render pro aluno

**Como** professor, **quero** inserir um widget no conteúdo da CU **para que** o aluno veja a mini-app junto ao material.

**Complexidade:** M-G · **Depende de:** E35-03, E35-04 · **Persona:** professor / aluno

### Critérios de Aceite
- [ ] Botão na toolbar do TinyMCE → abre picker dos **widgets disponíveis no curso** (`listAvailableForCourse`)
- [ ] Inserir grava o placeholder `[[widget:ID]]` no conteúdo
- [ ] Placeholder **sobrevive ao HTML Purifier** (sem precisar relaxar a allowlist de iframes)
- [ ] No render pro aluno o token é expandido:
  - [ ] `inline` → `<iframe sandbox="allow-scripts" src="/widget/serve/{id}/">` responsivo (16:9 ou dimensão sugerida)
  - [ ] `window` → ícone/botão que abre `/widget/open/{id}` em nova janela
- [ ] Widget inexistente/inativo referenciado → **placeholder gracioso** ("widget indisponível"), não quebra a página
- [ ] Mobile 360px (iframe inline encolhe)

### Tarefas técnicas
- [ ] Plugin/botão TinyMCE + modal de picker
- [ ] Função de expansão de `[[widget:ID]]` no pipeline de render do conteúdo (aluno **e** preview do professor)
- [ ] Garantir que o sanitizador preserva o token
- [ ] i18n PT/EN
- [ ] `php -l`

### Riscos
- **Sanitizador comendo o token:** validar que `[[widget:ID]]` passa intacto pelo HTML Purifier (é texto, não tag — deve passar).
- **Dual-render de conteúdo:** atenção ao [[feedback_form_dual_render]] se houver preview + edição na mesma tela.
