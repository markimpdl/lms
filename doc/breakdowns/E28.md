# E28 — Patentes informativas no ranking

> **Breakdown gerado em 2026-04-26.** Spec consolidada em `doc/15-roadmap-pos-mvp.md` (F19, linhas 1133–1153).

## Contexto

Grid de ranking (em `/student/ranking` e `/teacher/ranking`) hoje lista alunos com posição + nome + XP. Patentes (`ranks` por tenant) já existem desde E18 com `Rank::findCurrentByXp(totalXp)` + `rank.color_hex`. Mostrá-las inline contextualiza a progressão.

**Decisões simplificadoras:**
- Sem mudança de schema — só join/sub-select extra
- Comportamento idêntico em qualquer combinação (Actvet + LO ou grade ou não-Actvet) — patente é independente do modo de avaliação
- Aluno sem XP ou tenant sem patentes cadastradas → mostra `—`
- Performance: pré-computar via JOIN ou subselect (sem N+1)

---

## Story E28-01: Backend — RankingService::compute ganha rank por linha

**Como** sistema, **quero** que cada linha do ranking traga a patente atual do aluno **para que** a UI possa renderizar sem query extra por aluno.

**Complexidade:** P
**Depende de:** nenhuma (E18 ranks já existe)
**Persona:** infra/backend

### Critérios de Aceite
- [ ] `RankingService::compute()` retorna em cada row 3 campos novos: `rank_id`, `rank_name`, `rank_color_hex`
- [ ] Pré-computado via correlated subquery ou LATERAL join contra `ranks` — nada de N+1
- [ ] Lógica de "patente atual" inline na query: a `ranks` row do tenant onde `total_xp BETWEEN xp_min AND COALESCE(xp_max, MAX_INT)`
- [ ] Aluno sem XP suficiente OU tenant sem patentes cadastradas → 3 campos NULL
- [ ] Sem mudança de schema; index `idx_ranks_tenant_xp_min` (ou similar) — criar via ALTER se não existir

### Tarefas técnicas
- [ ] Auditar query de `RankingService::compute()` e adicionar subselect/JOIN
- [ ] Validar index existente em `ranks(tenant_id, xp_min, xp_max)`; criar se necessário
- [ ] Test mental + verificar EXPLAIN
- [ ] `php -l`

## Story E28-02: UI — coluna desktop + badge mobile

**Como** aluno/professor, **quero** ver a patente atual de cada aluno ao lado do XP **para que** o ranking ganhe contexto de progressão.

**Complexidade:** P
**Depende de:** #E28-01 (backend)
**Persona:** aluno + professor

### Critérios de Aceite
- [ ] `/student/ranking` (tabela desktop): nova coluna "Patente" entre Nome e XP — pill colorido com `rank_color_hex` + texto `rank_name`
- [ ] `/teacher/ranking` (tabela desktop): mesma coluna
- [ ] Cards mobile (ambas): badge pill ao lado do nome (decisão de design)
- [ ] Aluno sem patente: mostra `—` (em-dash, neutral-500)
- [ ] Tooltip opcional com `xp_min..xp_max` no hover (Bootstrap title attr)
- [ ] Mobile 360px: legível
- [ ] Dark mode: contraste OK (color_hex como bg + texto branco; ou aplicar mix se ruim)

### Tarefas técnicas
- [ ] `/student/ranking` page: tabela + cards
- [ ] `/teacher/ranking` page: tabela + cards
- [ ] CSS leve em `student-area.css` (provavelmente já tem `.lms-rank-pill` reusable da sidebar)
- [ ] `lang/pt.php` + `lang/en.php`: 1-2 chaves (`ranking.col.rank`, opcional `ranking.no_rank`)
- [ ] Mobile QA + dark mode QA
- [ ] `php -l`
