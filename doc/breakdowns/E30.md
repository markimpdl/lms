# E30 — Refazer template Skills Hub fiel ao PDF de referência

> **Breakdown gerado em 2026-04-27.** Spec consolidada em `doc/15-roadmap-pos-mvp.md` (F21, linhas 1185–1213).

## Contexto

A v1 do template Skills Hub (entregue em E26 / v0.23.0) foi gerada via Word "Save as Web Page Filtered" + dompdf. Resultado renderizou **diferente do PDF de referência do PO** — markup MSO-específico (`<!--[if gte mso 9]>`, VML, fontes Calibri/Arial sem fallback no dompdf, tabelas sem larguras explícitas). O pipeline de Reports (`ReportService` + trigger pós-LO + endpoint download + segurança) está OK e fica intacto. Só o template + renderer precisam de outra rodada.

Última iteração foi um **mau call meu** (recomendei "Save as HTML Filtered" como caminho de menor esforço; não considerei o limite de fidelidade do dompdf). Esta janela trata o problema com mais cuidado.

## Decisões consolidadas (2026-04-27 com PO)

- **Renderer:** trocar dompdf → **mPDF** (PHP-puro, composer-installable, melhor com tabelas/HTML moderno, fontes via TTF empacotada)
- **Sem serviço externo** (PDFShift/DocRaptor/etc.) — eliminado pelo PO (custo recorrente)
- **Template:** reescrever do zero em HTML/CSS limpo (sem markup MSO da v1)
- **Alvo de fidelidade:** "visualmente equivalente" ao PDF de referência (`template_reports/CU_SKILL_HUB_PDF.pdf`). Pixel-perfect cross-renderer não é meta realista.
- **Sem backfill** — PDFs antigos em prod ficam como estão; só novas gerações usam template/renderer novos
- **Plano B se mPDF + template limpo ainda tiver gaps inaceitáveis:** re-avaliar quando chegarmos lá. Opções abertas (não pré-decididas): FPDI overlay (importa o próprio PDF do PO + injeta texto via X/Y — fidelidade garantida mas posicionamento manual), TCPDF, ou lib que edite Word direto. Documentar gap específico antes de escolher.

## Restrições

- Manter **contrato de variáveis** (`{{NAME_*}}`, `{{WORKLOAD_UC}}`, `{{AVG_LEARN}}`, `{{LEARN_X_NAME}}`, `{{LEARN_X_SCORE}}`, etc.) — `ReportService::generate` não muda no que toca a substituição
- Path traversal defense + chroot do renderer preservados
- Hostinger compatível (PHP-puro; sem binary externo)
- FTP deploy do vendor mPDF: throttle igual ao usado pra dompdf (THROTTLE_MS=80 + RECONNECT_EVERY=50, já configurado em #338)

## Story E30-01: Swap dompdf → mPDF no `ReportService`

**Como** sistema, **quero** trocar a lib de PDF de dompdf pra mPDF **para que** o template novo (E30-02) possa ser desenvolvido em cima de um renderer com melhor suporte a HTML/CSS moderno e fontes empacotadas.

**Complexidade:** P
**Depende de:** nenhuma
**Persona:** infra/backend

### Critérios de Aceite
- [ ] `composer require mpdf/mpdf` instalado; vendor/ atualizado
- [ ] `ReportService::generate()` adaptado pra API mPDF (init, setHTML, output to file)
- [ ] Configuração de segurança equivalente: `tempDir` confinado a `storage/reports/`, sem network fetch (`mPdfConfig['curlAllowUnsafeSslRequests'] = false` ou similar)
- [ ] Path traversal defense preservada (template path validado, output path confinado a `LMS_ROOT/storage/reports`)
- [ ] Render do template atual (v1 MSO) com mPDF — **não espera fidelidade**, só confirma setup. PDF gerado é parseável e abre num leitor.
- [ ] dompdf REMOVIDO do composer.json (sem deixar dep órfã)
- [ ] vendor/dompdf/ deletado localmente após `composer update --no-dev`
- [ ] Smoke: gerar 1 report novo via UI (corrigir uma submission Actvet+LO) → PDF baixa OK
- [ ] FTP deploy do vendor mPDF: confirmar que throttle existente (#338) cobre o volume (mPDF tem ~150-200 arquivos, similar a dompdf)
- [ ] Doc `doc/19-reports.md` atualizado: seção "Renderer" troca dompdf → mPDF, decisão registrada

### Tarefas técnicas
- [ ] composer require + composer remove dompdf
- [ ] ReportService refactor (substitute dompdf calls)
- [ ] Smoke render local + prod
- [ ] Atualizar doc/19-reports.md
- [ ] `php -l` em ReportService

### Riscos
- **Vendor size:** mPDF empacota fontes TTF — vendor/ pode crescer. Mitigação: usar default fonts do mPDF + apenas DejaVu Sans/Serif; remover packs grandes de CJK/Arabic se mPDF carregar por default.
- **API breaking:** mPDF tem API distinta de dompdf. Refactor é local ao ReportService — não vaza pra outros lugares.

## Story E30-02: Reescrever template HTML/CSS limpo + validar fidelidade

**Como** professor (Actvet), **quero** que o report PDF gerado pra cada submission Actvet+LO renderize **visualmente equivalente** ao PDF de referência do Word **para que** eu possa entregar ao aluno um documento que se parece com o que mostro em sala.

**Complexidade:** M
**Depende de:** #E30-01 (mPDF)
**Persona:** professor (Actvet)

### Critérios de Aceite
- [ ] Novo `public/assets/report-templates/skill_hub/template.html` reescrito do zero
- [ ] HTML semântico (`<header>`, `<table>`, `<section>` com classes claras), zero markup MSO (`<!--[if gte mso]>`, VML, etc.)
- [ ] CSS embutido (`<style>` no `<head>`) — sem link pra externo, mPDF resolve melhor inline
- [ ] Fontes: usar família segura (`DejaVu Sans` ou `Helvetica` — built-in do mPDF). Se PO insiste em Calibri visual, considerar empacotar TTF (Calibri é proprietária; checar licença ou usar substituto livre como Carlito que é metric-compatible com Calibri)
- [ ] Tabelas com larguras explícitas (`<col width>` ou inline `width: Npx`) — mPDF lida muito melhor com larguras fixas
- [ ] Posicionamento simples (sem float complexo nem position: absolute pesado)
- [ ] Cores e espaçamentos batem visualmente com `template_reports/CU_SKILL_HUB_PDF.pdf` (lado-a-lado)
- [ ] Logo e imagens carregam corretamente (paths relativos ao template ou inline base64)
- [ ] Render gera PDF abrível, conteúdo correto, layout reconhecível
- [ ] Variáveis (`{{NAME_*}}`, `{{LEARN_X_*}}`, etc.) substituídas corretamente — contrato preservado da E26
- [ ] Validação manual: PO compara um PDF gerado vs o de referência e aprova ou aponta gaps específicos
- [ ] Se gap persiste após iteração no template:
  - [ ] Anotar gap específico em `doc/99-pendencias-tecnicas.md`
  - [ ] Trazer pro PO opções de plano B (FPDI overlay, TCPDF, edição direta de DOCX) com tradeoffs
  - [ ] Story #E30-03 (não criada nesta janela) cobriria a iteração de plano B
- [ ] Doc `doc/19-reports.md` ganha seção "Template v2" com decisões de fontes/CSS/quirks de mPDF

### Tarefas técnicas
- [ ] Estudar PDF de referência (estrutura, fontes aproximadas, espaçamentos, cores)
- [ ] Esqueleto HTML semântico + CSS skeleton
- [ ] Iterar render → comparar lado-a-lado → ajustar (provavelmente 3-5 iterações)
- [ ] Empacotar TTF de fonte se necessário (caminho de aprendizado: `mPDF\Config\FontVariables` + colocar TTF em `public/assets/fonts/`)
- [ ] Smoke com 2-3 submissions reais de tenant Actvet
- [ ] Atualizar doc/19-reports.md
- [ ] `php -l` se mexer em PHP (provavelmente só template HTML)

### Riscos
- **Fontes proprietárias do Word (Calibri):** licenciamento. Mitigação: usar Carlito (metric-compatible, livre) ou padrão DejaVu.
- **Layout de página A4 com margens Word vs mPDF:** ajustar `<style>@page { size: A4; margin: ... }` pra bater
- **PO ainda não aprovar fidelidade após N iterações:** sinaliza limite estrutural do mPDF. Aciona plano B (não escopo desta story).

## Pendências esperadas

- **Vendor mPDF size:** se vendor/ ficar grande demais (mPDF + fontes TTF), considerar `composer install --no-dev` em prod e excluir packs de fontes não usadas.
- **dompdf vendor remoção em prod:** após FTP deploy do mPDF, deletar manualmente `vendor/dompdf/` em prod via FileZilla pra liberar espaço (auto-deploy faz upload mas não delete).
- **Backfill:** decidido OFF — PDFs antigos ficam como estão. Se PO mudar de ideia, story futura simples (loop sobre `evaluation_submissions WHERE report_pdf_path IS NOT NULL` chamando `ReportService::generate`).
- **Plano B (FPDI overlay etc.):** documentado como opção mas só ativa se E30-02 não atingir fidelidade aceitável.
