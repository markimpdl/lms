# E29 — Identidade visual unificada teacher+admin

> **Breakdown gerado em 2026-04-26.** Spec consolidada em `doc/15-roadmap-pos-mvp.md` (F20, linhas 1157–1182).

## Contexto

Hoje só o aluno tem visual moderno (`lms-student-area`: Inter + Plus Jakarta Sans, page bg `#F8F7FB`, cards com `border-radius: 16px`, sombras suaves, eyebrow uppercase + título grande). Professor (`/teacher/*`) e super-admin (`/admin/*`) usam Bootstrap default — visualmente menos polido e inconsistente com a área do aluno.

**Decisões consolidadas (2026-04-26 com PO):**
- **Variants** (`lms-teacher-area`, `lms-admin-area`) reusando tokens — **não** promoção a genérica `lms-app-area`. Reduz risco de regressão na student.
- **Sem dark mode** pra teacher/admin no MVP — só aluno (escopo menor; pendência se PO pedir depois).
- **Sem sidebar** pra teacher/admin — só fontes + bg + Bootstrap overrides aplicados via body class. Reduz drasticamente o escopo (de 8 stories estimadas pra 4).
- **Migração gradual** — páginas não-migradas continuam Bootstrap default sem regressão.
- **1 release única** (v0.27.0) cobrindo o épico inteiro.

---

## Story E29-01: Tokens CSS pra `:root` + 2 shells (teacher + admin)

**Como** sistema, **quero** que professor e super-admin herdem fontes + page bg + overrides Bootstrap básicos via class no body **para que** todas as páginas `/teacher/*` e `/admin/*` ganhem o visual da student-area instantaneamente via cascade, sem precisar editar PHP de cada uma.

**Complexidade:** M
**Depende de:** nenhuma
**Persona:** infra/visual

### Critérios de Aceite
- [ ] Tokens `--lms-*` (cores, radii, shadows, fontes) movidos de `body.lms-student-area { ... }` pra `:root` em `app.css`. Aluno continua funcionando idêntico (regressão zero).
- [ ] `layout.php` ganha `$isTeacherArea` e `$isAdminArea` (gate por role + path prefix). Body recebe a class correspondente.
- [ ] `app.css` (ou novo `teacher-admin-area.css`) tem block compartilhado pelos dois `body.lms-teacher-area, body.lms-admin-area { ... }` aplicando: font-family Inter + Plus Jakarta Sans, page bg `#F8F7FB`, e overrides básicos do Bootstrap (`.card { border-radius: 16px; box-shadow: ...; }`, `.btn { font-weight: 600; }`, `.table { ... }`, `.form-control { border-radius: 10px; }`).
- [ ] Páginas teacher/admin existentes não quebram — smoke visual obrigatório das telas chave: `/teacher`, `/teacher/courses`, `/teacher/students`, `/teacher/groups`, `/teacher/settings`, `/admin`, `/admin/teachers`.
- [ ] Aluno continua intacto (smoke visual em `/student`, `/student/ranking`, `/profile`).
- [ ] Bootstrap-icons CSS carregado também pra teacher/admin (hoje só carrega em student) pra hero icons funcionarem nas próximas stories.

### Tarefas técnicas
- [ ] Mover tokens `:root` em `app.css` (acima dos overrides Bootstrap)
- [ ] Verificar que `body.lms-student-area { --lms-* }` continua funcionando (cascade ok)
- [ ] `layout.php`: `$isTeacherArea` (`role=teacher` + path `/teacher` ou `/teacher/*`); `$isAdminArea` (`role=super_admin` + path `/admin` ou `/admin/*`); body class condicional + load condicional de fonts + bootstrap-icons
- [ ] CSS shared block `body.lms-teacher-area, body.lms-admin-area { ... }`
- [ ] `php -l layout.php`
- [ ] Smoke das 7 páginas-chave + 3 do aluno

## Story E29-02: Polish páginas `/teacher/*` (hero + card grid)

**Como** professor, **quero** que minhas telas mais usadas tenham o mesmo nível de polish visual da área do aluno **para que** a experiência seja consistente e profissional independente do papel.

**Complexidade:** M
**Depende de:** #E29-01
**Persona:** professor

### Critérios de Aceite
- [ ] `/teacher` (dashboard): adopt `lms-dashboard-header` + `lms-dashboard-eyebrow` + `lms-dashboard-title` no cabeçalho da página
- [ ] `/teacher/courses` (index): hero pattern + cards de cursos no grid (similar ao `/student` cursos), em vez da tabela atual; manter info essencial (nome, matrícula count, ações)
- [ ] `/teacher/students` (index): hero pattern + tabela permanece (volume justifica), mas com header polido
- [ ] `/teacher/groups` (index): hero pattern + tabela polida
- [ ] `/teacher/settings/*`: hero pattern em cada sub-página principal (dados, notificações, avatares)
- [ ] Mobile: layout responsivo OK em 360px
- [ ] Páginas show/edit (`/teacher/courses/{id}/...`) **ficam pra depois** — escopo é só index/dashboard nesta story

### Tarefas técnicas
- [ ] Cada page handler: substituir `<h1 class="h3">...</h1>` solto por bloco `lms-dashboard-header`
- [ ] `/teacher/courses` index: trocar tabela por grid de cards (aproveitar componente reusável se existir, senão criar `lms-teacher-course-card` simples)
- [ ] CSS de suporte em `app.css` (ou block dedicado) pros novos componentes teacher
- [ ] i18n: chaves novas pra eyebrows (`teacher.dashboard.eyebrow`, `teacher.courses.eyebrow`, etc.) — adicionar em pt + en
- [ ] Smoke mobile + desktop
- [ ] `php -l` em cada PHP modificado
